# Решение

## Сколько заняло

Время не фиксировалось. Разработка выполнялась параллельно тремя ИИ-агентами под управлением основного агента.

## Что сделано и что не успел

Сделан экран матчей: карточки, загрузка, ошибка с повтором, пустые состояния, фильтры, обновление и избранное. Бонус — поиск по названию любого из клубов: помогает быстро найти нужный матч.

Код разделён по FSD: `app`, `pages`, `entities`, `features`, `shared`. Исходная папка `components` сохранена. Избранное хранится в памяти и сбрасывается после перезапуска.

Проверка на физическом устройстве в Expo Go и публикация изменений в удалённый репозиторий не выполнялись.

## Решения

- «Предстоящие» — `scheduled` и `postponed`: перенесённый матч ещё предстоит сыграть. «Завершённые» — только `finished`; `live` и неизвестные статусы доступны во «Все».
- Счёт `0:0` отображается как обычный счёт, отсутствие счёта — отдельно. Для отсутствующей даты показывается пояснение; время переводится в часовой пояс устройства. Фильтры опираются на статус сервера, а не на календарную дату.
- В исходном `MATCHES_URL` была заглушка `OWNER/REPO`. Она заменена на адрес `data/matches.json` в настоящем репозитории из `git origin`; другой сервер можно задать через `EXPO_PUBLIC_MATCHES_URL`. Сетевые ошибки показываются пользователю и не подменяются локальными данными.
- Добавлен совместимый с Expo Go `react-native-safe-area-context` для отступов от вырезов экрана. `tsx` и `@types/node` используются только при разработке: позволяют запускать TypeScript-тесты через встроенный `node:test` (`npm test`, Node.js 20+).

## Баги из части 2

1. Звёздочки: `Boolean(indexOf(id))` считал отсутствующий элемент (`-1`) избранным, а первый (`0`) — неизбранным. Массив также менялся на месте и передавался в React с прежней ссылкой, поэтому перерисовка могла не происходить; теперь проверка использует `includes`, а переключение создаёт новый массив через функциональное обновление состояния.
2. «Обновлено N сек назад»: интервал запоминал начальное значение `seconds`, поэтому каждый раз записывал одно и то же число; `since` не использовался, а интервал не очищался. Теперь время рассчитывается от последней успешной загрузки, пересчитывается при изменении `since`, а интервал удаляется при очистке эффекта.

## Как я использовал ИИ

Код и этот документ подготовлены Codex: задачи экрана, исправления компонентов и документации выполнялись параллельно. Автоматически прошли `npx tsc --noEmit`, все 8 тестов `npm test` и сборки Expo для web, iOS и Android; тесты проверяют фильтры, поиск, даты, нулевой счёт, неизвестные статусы, валидацию ответа и ошибки HTTP.

В Chrome через Playwright проверены реальные 8 матчей, фильтры (8/4/3), поиск и сброс, избранное, счёт `0:0`, отсутствие даты, часовой пояс Europe/Moscow, рост и сброс таймера, ширина 320 px без горизонтального переполнения. Подменённые ответы проверили HTTP 503, повтор загрузки, сохранение карточек при ошибке обновления и пустой список; ошибок выполнения не обнаружено.

Отдельные примеры ошибок в ответах ИИ не фиксировались. Ручная проверка пользователем пока не проводилась: перед сдачей нужно прочитать код и проверить приложение в Expo Go.

## Что улучшил бы, будь ещё 2 часа

Добавил бы сохранение избранного между запусками, автоматические проверки сетевых состояний и сценарии доступности с клавиатурой и экранным диктором.
