# Решение

## Сколько заняло

Время не фиксировалось. Разработка выполнялась параллельно тремя ИИ-агентами под управлением основного агента.

## Что сделано и что не успел

Сделан экран матчей с тёмной темой: карточки, загрузка, ошибка с повтором, пустые состояния, фильтры, обновление и избранное. Бонусы — поиск по названию любого из клубов и сохранение избранного между запусками: нужные матчи проще найти и не приходится отмечать повторно.

Код разделён по FSD: `app`, `pages`, `entities`, `features`, `shared`. Исходная папка `components` сохранена. Вкладка «Избранное» со счётчиком показывает отмеченные матчи текущего тура; поиск работает и в ней.

Проверка на физическом устройстве в Expo Go и публикация изменений в удалённый репозиторий не выполнялись.

## Решения

- «Предстоящие» — `scheduled` и `postponed`: перенесённый матч ещё предстоит сыграть. «Завершённые» — только `finished`; `live` и неизвестные статусы доступны во «Все».
- Счёт `0:0` отображается как обычный счёт, отсутствие счёта — отдельно. Для отсутствующей даты показывается пояснение; время переводится в часовой пояс устройства. Фильтры опираются на статус сервера, а не на календарную дату.
- В исходном `MATCHES_URL` была заглушка `OWNER/REPO`. Она заменена на адрес `data/matches.json` в настоящем репозитории из `git origin`; другой сервер можно задать через `EXPO_PUBLIC_MATCHES_URL`. Сетевые ошибки показываются пользователю и не подменяются локальными данными.
- Ответ сервера проверяется до отображения: обязательные строки не должны быть пустыми, тур должен быть положительным безопасным целым, счёт и минута — неотрицательными безопасными целыми; повторяющиеся id и некорректный JSON отклоняются. Неизвестные статусы сохраняются с русской подписью; прерванные и устаревшие запросы не перезаписывают актуальные данные.
- Избранное хранится через совместимый с Expo Go AsyncStorage 2.2: в браузере — в `localStorage` под ключом `matches-task:favorites:v1`, на устройстве — в нативном хранилище. При восстановлении проверяется массив id и удаляются дубликаты; ранние нажатия учитываются после чтения, записи выполняются последовательно. Ошибка хранилища показывается в уведомлении, отметки остаются доступны в памяти.
- Добавлен совместимый с Expo Go `react-native-safe-area-context` для отступов от вырезов экрана. `tsx` и `@types/node` нужны для TypeScript-тестов через встроенный `node:test` (`npm test`, Node.js 20+); `eslint` и `eslint-config-expo` — для проверки кода (`npm run lint`).

## Баги из части 2

1. Звёздочки: `Boolean(indexOf(id))` считал отсутствующий элемент (`-1`) избранным, а первый (`0`) — неизбранным. Массив также менялся на месте и передавался в React с прежней ссылкой, поэтому перерисовка могла не происходить; теперь проверка использует `includes`, а переключение создаёт новый массив через функциональное обновление состояния.
2. «Обновлено N сек назад»: интервал запоминал начальное значение `seconds`, поэтому каждый раз записывал одно и то же число; `since` не использовался, а интервал не очищался. Теперь время рассчитывается от последней успешной загрузки, пересчитывается при изменении `since`, а интервал удаляется при очистке эффекта.

## Как я использовал ИИ

Код и этот документ подготовлены Codex: задачи экрана, исправления компонентов и документации выполнялись параллельно. Прошли `npx tsc --noEmit`, `npx expo lint` без предупреждений, экспорты Expo для web, iOS и Android и все 19 тестов `npm test` (16 для матчей и 3 для избранного): фильтры, поиск, даты, нулевой счёт, неизвестные статусы, валидация ответа, ошибки HTTP и сохранённые id.

В Chrome через Playwright проверены реальные 8 матчей, фильтры (8/4/3), поиск и сброс, счёт `0:0`, отсутствие даты, часовой пояс Europe/Moscow, рост и сброс таймера. Подменённые ответы проверили HTTP 503, таймаут 15 секунд, повтор загрузки, сохранение карточек при ошибке обновления и пустой список.

Повторная проверка Chrome подтвердила сохранение избранного после перезагрузки, его вкладку, поиск и удаление последней отметки с пустым состоянием. Повреждённый JSON восстанавливается следующим действием, ошибка квоты показывается без падения и потери отметок в памяти; проверены ширины 320, 390, 600, 768, 820 и 1024 px.

Отдельные примеры ошибок в ответах ИИ не фиксировались. Проверка Expo Go на физическом устройстве не выполнялась.

Добавил бы в репозиторий воспроизводимые браузерные тесты, проверил доступность с экранным диктором и приложение в Expo Go на физическом устройстве.
