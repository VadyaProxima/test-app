# Решение

## Сколько заняло

Время не фиксировалось. Разработка выполнялась параллельно тремя ИИ-агентами под управлением основного агента.

## Что сделано и что не успел

Сделан экран матчей с тёмной темой: карточки, загрузка, ошибка с повтором, пустые состояния, фильтры, обновление и избранное. Бонусы — поиск по названию любого из клубов и сохранение избранного между запусками: нужные матчи проще найти и не приходится отмечать повторно.

Код разделён по FSD: `app/ui`, `pages/matches/{model,ui}`, `features/match-favorites/{model,ui}`, `entities/match/{api,model,ui}`, `shared/{config,ui}`. Слайсы и сегменты Shared экспортируются через публичные `index.ts`; `components` оставлен только для совместимых реэкспортов, рабочий код от него не зависит. Вкладка «Избранное» со счётчиком показывает отмеченные матчи текущего тура; поиск работает и в ней.

Изменения сохранены в feature-ветке `feat/matchday`; слияние в `main` оставлено пользователю. Проверка на физическом устройстве в Expo Go не выполнялась.

## Решения

- «Предстоящие» — `scheduled` и `postponed`: перенесённый матч ещё предстоит сыграть. «Завершённые» — только `finished`; `live` и неизвестные статусы доступны во «Все».
- Счёт `0:0` отображается как обычный счёт, отсутствие счёта — отдельно. Для отсутствующей даты показывается пояснение; время переводится в часовой пояс устройства. Фильтры опираются на статус сервера, а не на календарную дату.
- В исходном `MATCHES_URL` была заглушка `OWNER/REPO`. Она заменена на адрес `data/matches.json` в настоящем репозитории из `git origin`; другой сервер можно задать через `EXPO_PUBLIC_MATCHES_URL`. Сетевые ошибки показываются пользователю и не подменяются локальными данными.
- Ответ сервера проверяется до отображения: обязательные строки не должны быть пустыми, тур должен быть положительным безопасным целым, счёт и минута — неотрицательными безопасными целыми; повторяющиеся id и некорректный JSON отклоняются. Неизвестные статусы сохраняются с русской подписью; прерванные и устаревшие запросы не перезаписывают актуальные данные.
- Избранное хранится через совместимый с Expo Go AsyncStorage 2.2: в браузере — в `localStorage` под ключом `matches-task:favorites:v1`, на устройстве — в нативном хранилище. При восстановлении проверяется массив id и удаляются дубликаты; ранние нажатия учитываются после чтения, записи выполняются последовательно. Ошибка хранилища показывается в уведомлении, отметки остаются доступны в памяти.
- `MatchCard` получает слот `actions`, а страница размещает в нём кнопку избранного: сущность матча не зависит от фичи. Локальные компоненты страницы, включая пустое состояние, находятся в её `ui`; общий интерфейс вынесен в `shared/ui`.
- Поле поиска и шапка находятся вне `FlatList`, поэтому ввод не меняет высоту прокручиваемой области и не вызывает скачков страницы. Результаты занимают отдельную область с `flex: 1` и `minHeight: 0`; на узком экране шапка компактнее.
- Добавлен совместимый с Expo Go `react-native-safe-area-context` для отступов от вырезов экрана. `tsx` и `@types/node` нужны для TypeScript-тестов через встроенный `node:test` (Node.js 20+); `eslint` и `eslint-config-expo` — для проверки кода; `@playwright/test` — для воспроизводимых браузерных сценариев.

## Баги из части 2

1. Звёздочки: `Boolean(indexOf(id))` считал отсутствующий элемент (`-1`) избранным, а первый (`0`) — неизбранным. Массив также менялся на месте и передавался в React с прежней ссылкой, поэтому перерисовка могла не происходить; теперь проверка использует `includes`, а переключение создаёт новый массив через функциональное обновление состояния.
2. «Обновлено N сек назад»: интервал запоминал начальное значение `seconds`, поэтому каждый раз записывал одно и то же число; `since` не использовался, а интервал не очищался. Теперь время рассчитывается от последней успешной загрузки, пересчитывается при изменении `since`, а интервал удаляется при очистке эффекта.

## Как я использовал ИИ

Код и этот документ подготовлены Codex: задачи экрана, исправления компонентов и документации выполнялись параллельно. Прошёл `npm run check`: TypeScript, Expo ESLint и все 22 теста — 16 для матчей, 3 для избранного и 3 для архитектуры. Проверки архитектуры разбирают импорты через AST, контролируют направление зависимостей и публичные API, разрешение импортов и отсутствие циклов. Финальный `npx expo export --platform all` собрал web, iOS и Android.

Все 6 браузерных тестов `tests/browser/matches.spec.ts` прошли: на четырёх ширинах проверены поиск с изменением числа карточек `8 → 1 → 0 → 8` и стабильность положения поля, списка, подвала и страницы, сохранение избранного и удаление из его вкладки, ошибка HTTP, повтор и сохранение прежних данных при ошибке обновления. Запуск: `npx playwright install chromium`, затем `npm run test:browser`; для системного Chrome можно задать `PLAYWRIGHT_CHANNEL=chrome`.

Дополнительно в Chrome проверены реальные 8 матчей, фильтры (8/4/3), счёт `0:0`, отсутствие даты, часовой пояс Europe/Moscow, рост и сброс таймера, таймаут 15 секунд, повреждённое хранилище и ошибка квоты без потери отметок в памяти. Адаптивность проверялась на ширинах 320, 390, 600, 768, 820 и 1024 px.

Отдельные примеры ошибок в ответах ИИ не фиксировались. Проверка Expo Go на физическом устройстве не выполнялась.

## Что улучшил бы, будь ещё 2 часа

Проверил бы доступность с экранным диктором и приложение в Expo Go на физическом устройстве; расширил бы браузерные сценарии проверкой часовых поясов и ошибок хранилища.
